# Grain G-01 — SEND workflow update, 2026-11-18

Production editor update; no granular algorithm, parameter ID/order/range,
default, state schema, voice limit, routing limit or sample storage change.
New block-end lock-free telemetry exposes capture state, stored duration and
effective birth density. No new DSP allocation or synchronization mechanism.

Verified during implementation:

- Existing Grain engine, JUCE adapter and actual VST3-host tests pass (3/3).
- New editor regression failed against the old matrix-only UI, then passed with
  the SEND implementation. It exercises source/destination actions, actual audio
  capture through A > B > C, self/cyclic feedback, matrix/inspector synchronization,
  momentary keyboard press/release, nonzero restoration, automation takeover,
  editor-close release, morph handoff (including the existing 0.01 gain-step
  quantization) and two-click clear protection.
- Route removal leaves frozen A/B PCM unchanged. Performed recursive memories
  round-trip sample-for-sample through serialized plugin state. Host playhead
  simulation covers loop restarts, negative and distant seeks, tempo change and
  stopped synced births without replacing held audio. This is not Cubase testing.
- Workflow callbacks are audited for allocation/free; the existing calibrated
  adapter audit also checks OS lock/file/write calls at six sample rates.
- Native default/minimum, Details and Matrix editor images are generated by the
  actual JUCE editor. Minimum and Details were visually inspected at 1120x800;
  all primary controls remain inside the editor.
- Eight-second adapter baseline WAV is byte-identical before/after: SHA-256
  `30ccc0f740713d5f0892cfd1b5a23374d45bd8fedd65b998fb7003c36ea7f8be`,
  peak 0.0702784, RMS 0.0192104. Audio was rendered, not subjectively assessed.
  The workflow test additionally renders `send-performance.wav` through the
  actual plugin processor; it is a diagnostic phrase, not a musical endorsement.

One local Release benchmark during this pass (127-frame calls, saturated pools):
48 kHz Sinc16 median 339.375 us, p99 370.917 us, max 392.916 us against
2645.83 us; 192 kHz median 119.625 us, p99 136.583 us, max 140.417 us against
661.458 us. Desktop wall-clock measurements are not realtime guarantees or a
controlled performance comparison with the historical build below.

Reproduce with `cmake --build build-recall --target grain_plugin_tests
GrainG01_VST3 --parallel 4`, then `ctest --test-dir build-recall -R grain
--output-on-failure`. Native editor PNGs and workflow WAV are in
`build-recall/grain_editor_artifacts/`. `grain_plugin_tests --render <folder>`
writes the unchanged eight-second baseline. Full-family Release and Grain
ASan/UBSan checks are delivery gates; `/tmp/aste-grain-proof/` holds the local
commit-bound contract and receipts. Build/install architecture for this update
is native arm64 for the creator's Apple-silicon Mac, not a new universal claim.

Open validation: Cubase on the other Mac, subjective musical usefulness,
VoiceOver and physical mouse/keyboard performance in a real DAW window. UI
gestures are tested by dispatching native component actions/keyboard handlers;
screenshots are real editor renders, not a desktop usability session. Host
automation remains block-boundary, not sample-accurate VST3 automation. Active
grains/playheads/unfinished captures are not stored; completed source audio is.
